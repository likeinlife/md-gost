# Диаграммы IDEF0 под md-gost

Нотацию рисует пакет `idef0` сборщика, не PlantUML. Полный справочник,
палитра и класс `Waterfall` — в
<https://github.com/likeinlife/md-gost/blob/main/packages/idef0/README.md>.
Текст главы вокруг рисунка пишет скилл `gost-doc`: ссылка `[@fig:…]` до
рисунка, вывод после него, раздел рисунком не заканчивается.

Новую диаграмму пишите текстом `.idef0`. Python оставляйте для уже
существующего `.py`. Образец контекста в этом репозитории —
`semestr_3/it_management/lab7/diagrams/context.idef0`.

## Куда класть

Файл — в каталог работы (там, где `book.toml`), обычно `diagrams/`.
Вставка в главу, путь относительно этого каталога:

```markdown
Контекстная диаграмма приведена на рисунке [@fig:context].

![Контекстная диаграмма деятельности](diagrams/context.idef0){#fig:context}
```

Короткую диаграмму можно вложить в главу. Подпись здесь — атрибут `caption`,
как у листинга:

````markdown
```{.idef0 #fig:release caption="Разработка и проверка системы"}
block A1 : Разработать систему
block A2 : Проверить систему
input -> A1 : Задание
A1 -> A2 : Версия
A2 -> output : Проверенная система
```
````

В подписи файла не ставьте прямые двойные кавычки: их ловит `TYPO002`.
Номер «Рисунок N» в тексте не набирается.

После правки соберите работу и откройте PNG в `.md-to-gost/img/`. Сборка
проверяет модель, но не читаемость подписей. Если подписи наползают друг на
друга, укоротите текст, поставьте явный перенос `\n` или уберите стрелку,
которая пересекает весь каскад.

## Что куда входит

Стрелка — не украшение. Роль выбирают по смыслу, и от роли зависит сторона
блока.

| Роль | Сторона | Что это |
| --- | --- | --- |
| Вход | слева | То, что функция превращает в результат |
| Управление | сверху | Правило или ограничение; само результатом не становится |
| Выход | справа | Результат функции |
| Механизм | снизу | Кто или чем выполняет функцию; на выход не выходит |

Контекст — одна функция на границе деятельности, обычно `A0`. Декомпозиция
раскрывает её на 2–6 частей. Коды и порядок блоков в тексте декомпозиции
совпадают с процессами в главе. Замечание на доработку возвращают
управлением. Материал для нового разбора (предложение, заявка) возвращают
входом. Ограничение, общее для всех блоков, вешают одной стрелкой на `*`,
а не отдельной длинной стрелкой с первого блока на последний.

## Контекст

Первая строка — `context`, дальше каждая строка добавляет свою стрелку.
Пустые строки и строки с `#` пропускаются. Первое двоеточие отделяет
команду от подписи; внутри подписи двоеточие допустимо. Перенос — `\n`.

```text
context A0 : Внедрять и\nсопровождать\nсистемы 1С
input : Заявка и сведения о потребности
input : Обращения пользователей
output : Принятая система и акт
output : Решённые обращения и отчёт
control : Договор и бюджет
control : Политика качества
mechanism : Сотрудники
mechanism : Платформа и средства учёта
```

На контексте несколько стрелок на одной стороне нормальны. Подписи держите
короткими: холст не растягивается под абзац.

## Декомпозиция

Порядок строк `block` — основная цепочка слева направо и сверху вниз.
Между каждой соседней парой ровно одна стрелка без роли. Ещё одна такая же
стрелка — ошибка; обратная связь без роли тоже ошибка.

```text
block A1 : Согласовать\nтребования
block A2 : Включить\nв портфель
block A3 : Настроить\nи доработать
block A4 : Проверить\nи передать
block A5 : Сопровождать\nпо SLA

input -> A1 : Заявка
input -> A2 : Внутренняя\nинициатива
input -> A5 : Обращения
A1 -> A2 : Требования\nи критерии
A2 -> A3 : Задание
A3 -> A4 : Версия и\nдокументы
A4 -> A5 : Система и\nматериалы
A4 -> output : Система\nи акт
A5 -> output : Отчёт\nпо SLA

control -> * : Договор, бюджет, политика качества
mechanism -> * : Сотрудники и платформа

A5 -> A1.input : Предложения\nпо изменениям
A1 -> A4.control : Критерии\nприёмки
A4 -> A3.control : Замечания\nна доработку
A4 -> A5.control : Параметры\nзащиты
```

Не дублируйте подпись цепочки отдельным управлением с тем же словом.
Стрелка `A1 -> A3.control : Требования` рядом с `Требования и критерии`
ставится вплотную к ней, и на рисунке читаются две одинаковые подписи.

Дополнительные формы адресата:

| Запись | Смысл |
| --- | --- |
| `control -> *` | Одно общее управление на все блоки. Второе `*` на той же стороне нельзя |
| `mechanism -> *` | Один общий механизм на все блоки |
| `control -> A2` | Индивидуальная стрелка одному блоку |
| `control -> A1,A2` | Группа: не меньше двух кодов и не больше четырёх групп на сторону |
| `A4 -> A3.control` | Результат одного блока управляет другим |
| `A5 -> A1.input` | Результат одного блока входит в другой |
| `input -> A1` | Внешний вход. У блока такой вход только один |
| `A4 -> output` | Внешний выход. У блока такой выход только один |

Роли у дополнительной связи только `.input` и `.control`. Механизм из блока
в блок не задаётся. Код блока — буквы, цифры, `_` и `-`. Слова `context`,
`block`, `input`, `output`, `control`, `mechanism` кодами не бывают.

Пределы, на которых модель отклоняется:

- блоков от 2 до 6, коды уникальны;
- основная цепочка соединяет только соседей в порядке объявления, без пропусков;
- один внешний вход и один внешний выход на блок;
- на сторону управления и на сторону механизмов — одна общая стрелка, до четырёх групп и до шести индивидуальных стрелок у каждого блока;
- два входа извне в один блок нельзя развести двумя стрелками: объедините подписи в одну или направьте второй вход в другой блок.

Цвет по умолчанию чёрный на белом, для учебной работы его не меняют. Если
цвет нужен, атрибуты пишут до двоеточия: `A2 -> A1.control [color=orange] : Замечания`.
Имена палитры: `black`, `white`, `gray`, `red`, `orange`, `yellow`, `green`,
`teal`, `blue`, `purple`; либо `#RGB` и `#RRGGBB`.

## Python, если файл уже есть

Сборщик сам импортирует `idef0`. Результат должен называться `diagram`,
`fig` или `g`. Для печатной работы берите `style="report"`.

```python
from idef0 import Decomposition, draw

model = Decomposition()
model.step("A1", "Согласовать\nтребования")
model.step("A2", "Включить\nв портфель", from_previous="Требования\nи критерии")

model.input("Заявка", to="A1")
model.output("Система\nи акт", source="A2")
model.control("Договор и бюджет")
model.mechanism("Сотрудники")
model.input("Предложения", source="A2", to="A1")
model.control("Замечания", source="A2", to="A1")

fig = draw(model, style="report")
```

У первого `step` аргумента `from_previous` нет, у каждого следующего он
обязателен. `input` и `output` без `source` — внешние, и повтор на тот же
блок падает. `control` и `mechanism` без `to` — общая стрелка; `to` строкой
адресует один блок, списком — группу. Межблочное управление требует один
код в `to` и `source`. У `mechanism` источника-блока нет.

Контекст в Python, если текстовый файл не используют:

```python
from idef0 import Block, Context

diagram = Context(
    Block("A0", "Разработать систему"),
    inputs=["Заявка", "Обращения"],
    outputs=["Принятая система", "Отчёт"],
    controls="Договор",
    mechanisms="Команда",
)
```

## Проверка

1. Сверьте рисунок с абзацами: каждая стрелка, названная в тексте, есть на схеме, и на схеме нет стрелки, которую текст не объясняет.
2. Запустите `md-gost build` каталога работы. `ModelError` указывает строку `.idef0` или нарушенный предел; синтаксис не заменяют другим, пока не исправлена эта строка.
3. Посмотрите PNG. Налегающие подписи укорачивают. Стрелку через весь каскад, если правило и так общее, заменяют на `control -> *` или `mechanism -> *`.
