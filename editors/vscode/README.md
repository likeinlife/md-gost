# Markdown ГОСТ для VS Code

Расширение форматирует Markdown с таблицами Pandoc. В главах из `book.toml` оно также добавляет подсветку ГОСТ-разметки, автодополнение, переходы по ссылкам и быстрые исправления замечаний `md-lint`.

Тот же сервер подключается к [Zed](../zed/README.md). Cursor ставит это расширение как обычное расширение VS Code.

## Установка

1. Из корня репозитория установите пакет с поддержкой LSP. Для обновления ранее установленной копии добавьте к команде `--reinstall`.

   ```sh
   uv tool install '.[lsp]'
   ```

   Проверьте, что команда видна в терминале: `where.exe md-gost` в Windows, `command -v md-gost` в macOS и Linux. Сервер запускается как `md-gost lsp`.

2. Для сборки расширения нужен Node.js. В каталоге `editors/vscode` установите зависимости и соберите клиент.

   ```sh
   npm install
   npm run compile
   ```

3. Упакуйте расширение и установите его в редактор, из которого открыт этот репозиторий.

   ```sh
   npm run package
   cursor --install-extension md-gost-lsp-0.1.0.vsix
   ```

   Для VS Code замените `cursor` на `code`. После установки выполните `Developer: Reload Window`. Пока клиент меняется, вместо упаковки можно запустить конфигурацию «Markdown ГОСТ» из корня репозитория: она открывает новое окно с этим каталогом как расширением в разработке. [Расширения в режиме разработки](https://code.visualstudio.com/api/working-with-extensions/testing-extension)

Сервер подхватывает Markdown сразу после установки. В этом репозитории форматтер, семантическая подсветка и сохранение пробелов в конце строк уже заданы в `.vscode/settings.json`. Чтобы подключить его в другой работе, добавьте в её `.vscode/settings.json` следующий фрагмент.

```json
{
  "[markdown]": {
    "editor.defaultFormatter": "md-gost.md-gost-lsp",
    "editor.semanticHighlighting.enabled": true,
    "files.trimTrailingWhitespace": false
  }
}
```

Семантические токены сохраняют подсветку Markdown и добавляют цвета темы для меток, языков блоков и имён атрибутов. Значение `false` отключает этот слой. [Семантическая подсветка в VS Code](https://code.visualstudio.com/api/language-extensions/semantic-highlight-guide)

## Исправления и форматирование

- В главе поставьте курсор на замечание и нажмите `Ctrl+.` (`⌘.` на macOS, команда `editor.action.quickFix`). Например, для лишнего пробела перед запятой можно выбрать исправление `TYPO003`. Действие «md-lint: исправить всё в главе» применяет все доступные механические исправления к текущей главе.
- Выполните «Форматировать документ» (`Shift+Alt+F`, на macOS `⇧⌥F`), чтобы убрать лишние пробелы и выровнять таблицы во всём файле. Для фрагмента выделите текст и вызовите «Форматировать выделенный фрагмент». Если выделение затрагивает таблицу, форматтер выравнивает её целиком, сохраняя объединения ячеек. В тексте сохраняются явные переносы строк Markdown и пробелы внутри кода.
- Чтобы запускать тот же форматтер и по сохранению, добавьте `"editor.formatOnSave": true` в настройки `[markdown]`. Параметр `files.trimTrailingWhitespace` в примере выше передаёт форматтеру исходные пробелы в конце строк, по которым он распознаёт явные переносы. [Форматирование при сохранении](https://code.visualstudio.com/docs/editing/codebasics#_formatting)

## Проверка в редакторе

1. Откройте `example/CHAPTER_1.md`. В предложении перед таблицей «Сравнение CASE-инструментов» сократите ссылку до `[@tbl:to]` и поставьте курсор перед закрывающей скобкой. Вызовите дополнение (`Ctrl+Space`) и выберите `tbl:tools`. Должна получиться исходная ссылка `[@tbl:tools]`.
2. Наведите указатель на `fig:usecase` в ссылке `[@fig:usecase]`. В подсказке появится подпись «Диаграмма вариантов использования». Клавиша F12 откроет объявление рисунка в той же главе.
3. Откройте рядом `example/INTRO.md` и `example/REFERENCES.md`. В последнем временно измените ключ `#bib:urintsov` на `#bib:urintsov-test`. Ещё до сохранения во введении у ссылки на Уринцова появится `REF003`. Отмените правку, чтобы убрать замечание.
4. В `example/INTRO.md` поставьте курсор на «приложении А» и нажмите F12. Откроется заголовок в `APPENDIX_A.md`. Нажмите Shift+F12 на этом заголовке, чтобы увидеть упоминания приложения.
5. В тексте главы наберите `#bib:opachki`. Оставьте курсор на ключе и вызовите быстрое исправление. Выберите «Добавить источник bib:opachki». В главе появится `[@bib:opachki]`, а редактор переведёт курсор на поле «Описание источника» в новой записи. Чтобы добавить запись вручную, введите `bib` на отдельной строке и выберите сниппет «Источник».

## Если сервер не запустился

Откройте панель «Вывод» и выберите канал `md-gost-lsp`. Проверьте, что файл открыт как Markdown, а расширение установлено и включено. Если редактор показывает Restricted Mode для вашего репозитория, доверьте папку: сервер запускает локальную команду. После исправления настроек выполните «Markdown ГОСТ: Перезапустить сервер». [Режим доверия к рабочей области](https://code.visualstudio.com/docs/editing/workspaces/workspace-trust)

Если редактор не находит команду, скопируйте путь из `where.exe md-gost` или `command -v md-gost` в пользовательские настройки. Это особенно удобно, если графическое приложение получает другой `PATH`. Стандартный запуск — `md-gost lsp` по stdin/stdout.

```json
{
  "md-gost-lsp.path": "C:\\Users\\имя\\.local\\bin\\md-gost.exe",
  "md-gost-lsp.args": ["lsp"]
}
```
