# Markdown ГОСТ для Zed

Расширение форматирует Markdown с таблицами Pandoc. В главах из `book.toml` оно также добавляет подсветку ГОСТ-разметки, автодополнение, переходы по ссылкам и быстрые исправления замечаний `md-lint`.

## Установка

1. Из корня репозитория установите пакет с поддержкой LSP. Для обновления ранее установленной копии добавьте к команде `--reinstall`.

   ```sh
   uv tool install '.[lsp]'
   command -v md-gost
   ```

2. Для локальной сборки расширения Zed использует Rust из rustup. Добавьте цель WebAssembly.

   ```sh
   rustup target add wasm32-wasip2
   ```

3. Откройте корень репозитория в Zed. В палитре команд выберите `zed: install dev extension` и укажите каталог `editors/zed`. После изменения адаптера повторите установку. [Разработка расширений Zed](https://zed.dev/docs/extensions/developing-extensions)

Сервер включён для Markdown в настройках этого проекта. Чтобы подключить его в другой работе, добавьте в её `.zed/settings.json` следующий фрагмент. Элемент `"..."` сохраняет другие языковые серверы для Markdown. [Настройка языковых серверов Zed](https://zed.dev/docs/extensions/languages#opt-in-language-servers)

```json
{
  "languages": {
    "Markdown": {
      "language_servers": ["md-gost-lsp", "..."],
      "semantic_tokens": "combined",
      "formatter": { "language_server": { "name": "md-gost-lsp" } },
      "remove_trailing_whitespace_on_save": false
    }
  }
}
```

Режим `combined` сохраняет подсветку Markdown и добавляет цвета темы для меток, ссылок, языков блоков и имён атрибутов. Значение `off` отключает этот слой. [Семантическая подсветка в Zed](https://zed.dev/docs/semantic-tokens)

## Исправления и форматирование

- В главе поставьте курсор на замечание и нажмите `⌘.` (`editor: toggle code actions`). Например, для лишнего пробела перед запятой можно выбрать исправление `TYPO003`. Действие «md-lint: исправить всё в главе» применяет все доступные механические исправления к текущей главе.
- Выполните `editor: format`, чтобы убрать лишние пробелы и выровнять таблицы во всём файле. Для фрагмента выделите текст и вызовите `editor: format selections`. Если выделение затрагивает таблицу, форматтер выравнивает её целиком, сохраняя объединения ячеек. В тексте сохраняются явные переносы строк Markdown и пробелы внутри кода.
- Чтобы запускать тот же форматтер и по `⌘S`, добавьте `"format_on_save": "on"` в настройки `languages.Markdown`. Параметр `remove_trailing_whitespace_on_save` в примере выше передаёт форматтеру исходные пробелы в конце строк, по которым он распознаёт явные переносы. [Настройки Markdown в Zed](https://zed.dev/docs/languages/markdown)

## Проверка в редакторе

1. Откройте `example/CHAPTER_1.md`. В предложении перед таблицей «Сравнение CASE-инструментов» сократите ссылку до `[@tbl:to]` и поставьте курсор перед закрывающей скобкой. Вызовите дополнение и выберите `tbl:tools`. Должна получиться исходная ссылка `[@tbl:tools]`.
2. Наведите указатель на `fig:usecase` в ссылке `[@fig:usecase]`. В подсказке появится подпись «Диаграмма вариантов использования». Команда `editor: go to definition` откроет объявление рисунка в той же главе.
3. Откройте рядом `example/INTRO.md` и `example/REFERENCES.md`. В последнем временно измените ключ `#bib:urintsov` на `#bib:urintsov-test`. Ещё до сохранения во введении у ссылки на Уринцова появится `REF003`. Отмените правку, чтобы убрать замечание.
4. В `example/INTRO.md` поставьте курсор на «приложении А» и нажмите F12. Откроется заголовок в `APPENDIX_A.md`. Нажмите Shift+F12 на этом заголовке, чтобы увидеть упоминания приложения.
5. В тексте главы наберите `#bib:opachki`. Оставьте курсор на ключе и вызовите `editor: toggle code actions`. Выберите «Добавить источник bib:opachki». В главе появится `[@bib:opachki]`, а Zed переведёт курсор на поле «Описание источника» в новой записи. Чтобы добавить запись вручную, введите `bib` на отдельной строке и выберите сниппет «Источник».

## Если сервер не запустился

Откройте в палитре Zed `dev: open language server logs` и выберите `md-gost-lsp`. Проверьте, что файл открыт в режиме Markdown, в настройках проекта включён сервер, а расширение установлено. Если Zed показывает Restricted Mode для вашего репозитория, просмотрите настройки проекта и разрешите запуск инструментов для этой папки. После исправления настроек выполните `editor: restart language server`. [Режим доверия к проекту](https://zed.dev/docs/worktree-trust)

Если Zed не находит команду, скопируйте путь из вывода `command -v md-gost` в **пользовательские** настройки Zed. Это особенно удобно, если графическое приложение получает другой `PATH`. Стандартный запуск — `md-gost lsp` по stdin/stdout. Если указан только путь, расширение само добавляет аргумент `lsp`.

```json
{
  "lsp": {
    "md-gost-lsp": {
      "binary": {
        "path": "/полный/путь/к/md-gost",
        "arguments": ["lsp"]
      }
    }
  }
}
```
