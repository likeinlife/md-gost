# md-gost-postlint

Постлинтер готовых `.docx`. В отличие от `md-gost lint`, он разбирает OOXML
внутри итогового документа после Pandoc и постобработки.

Постлинтер запускается автоматически при `md-gost build`. Отдельно:

```bash
md-gost postlint path/to/file.docx
```

Проверки сейчас выдают предупреждения:

| Код | Что проверяется |
|-----|-----------------|
| `POST001` | хотя бы одна строка таблицы не защищена от разрыва между страницами (`w:cantSplit`) |
| `POST002` | встроенное изображение занимает более 65% печатной высоты страницы |
| `POST003` | высота встроенного изображения превышает физическую высоту страницы |
| `POST004` | строка шапки таблицы не удерживается вместе со следующей строкой (`w:keepNext`) |
| `POST005` | подпись таблицы или листинга не удерживается с объектом |
| `POST006` | подпись рисунка не удерживается с изображением |
| `POST007` | формула не удерживается вместе с пояснением |
| `POST008` | начало таблицы не удерживает первые три строки данных с подписью и шапкой |

Постлинтер использует только стандартную библиотеку Python. Ошибки чтения
повреждённого `.docx` дают ненулевой код; найденные риски верстки пока остаются
предупреждениями, чтобы оценить их на реальных работах до включения блокирующих
правил.

OOXML хранит размеры объектов, но не координаты после пагинации. Поэтому
проверка размера медиа может указать на риск пустого места, но не определяет,
осталась ли таблица в последних строках страницы. Для точного контроля таких
случаев нужен этап рендеринга в PDF с анализом геометрии страниц.
